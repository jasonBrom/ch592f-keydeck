C5 AAC0809 1.15：Windows 原生轮盘慢转输入修复
2026-10-20

本版针对的问题
用户选择的是按住旋钮呼出的 Windows 轮盘菜单中的“滚动”。固件 1.14 在每 4 边沿上报 10°时，用户实测仍为“慢转不滚动，快转能滚动”。直接鼠标滚轮模式慢转有效，但不能据此认定原生轮盘的滚动已修复。
两次只读 HID 采集没有录到有效旋转数据，不能据此断言 Windows 丢弃了数据。当前修复针对固件确实存在的粗粒度上报间隔；实际 Windows 滚动效果已在本机由用户验收，见文末记录。

1.15 的行为
原生轮盘模式始终按有效编码器边沿采样。每个边沿发送配置角度的 1/N，N 为所选的触觉边沿数；本地转动触觉仍累计 N 个边沿才触发一次。
目前已保存配置为 encoderMode=0、transitions=4、angle=100：
- 每个有效边沿发送 2.5°，4 个同向边沿累计发送 10°。
- 触觉仍为 4 个边沿一次，按 20 脉冲／圈估算约 18°实体转动一次触觉。
- 部分角度不足 0.1°时保留余数，反转抵消余量；不补造移动量，不按速度放大角度。
- USB、蓝牙使用相同的输入规则，仍走原生 Radial Controller。
- 直接鼠标滚轮、音量与自定义映射保留各自的计步规则。
应用、通道切换会清除待发送输入和细分余量。配置格式、HID 描述符和 DataFlash 布局不变。

网页
修复读取后旋钮用途选择框未同步的问题；按设备实际固件版本说明细分输入与触觉间距。Windows 菜单内的滚动和直接鼠标滚轮是两种有效用途。

烧录与验证
1. 使用本版 HEX 和配套 ISP.ini，保留 DataFlash。按住 BOOT 后通过 USB 复位／上电进入 ISP；不能通过当前 BLE 配置通道更新固件。
2. 烧录并重启后读取设备，固件应为 1.15，原配置仍应为原生轮盘、4 边沿、累计 10°。
3. 按住旋钮，选择 Windows 轮盘菜单的“滚动”，在普通长网页正文上分别慢转与快转；再检查菜单是否仍约 18°一项。
4. 若慢转仍无效，需要继续检查 Windows 原生滚动处理；不能把本版单元测试通过当作实机问题已解决。1.14 镜像保留以供回退。

验证范围
主机回归覆盖实际编码器 ISR、USB/BLE 输入、细分角度总量、反转、发送拥塞和触觉间距。C/JS 集成覆盖浏览器配置读写、保存重启和生产细分编译选项。本机已完成烧录、版本和配置回读，以及用户对原生滚动和菜单切项的验收。

本机实机验收（2026-10-20）
用户完成烧录并重启；独立 BLE 只读回读确认固件 1.15、能力 0x79ffff、原生轮盘、4 边沿、累计 10°，实际 BLE 间隔 7.5 ms。1024 字节配置与烧录前已保存版本完全一致，验收期间未修改设备配置或 Flash。
用户反馈：Windows 菜单“滚动”中“慢转已能连续滚动”；轮盘菜单“幅度合适，基本一响一项”。这是本机当前 Windows 与所测网页的结果，未测量端到端延迟，其他应用的角度阈值仍由应用和系统决定。
